## 0. TL;DR 与不可变目标

用 **Python + moderngl（GLSL）** 编写离线工具，读取桌布的已烘焙数据图，在纹理空间逐 texel 计算**风格化卡通各向异性高光**，实时调整参数，最终导出 **2048×2048 PNG 光照颜色图**。

- albedo 固定为白；不要求输入底色图，不实现 GGX/Ward 等 PBR BRDF。
- 采用位移切线 Kajiya–Kay 变体与卡通分段；这是艺术光照模型，不宣称物理正确。
- 工具本体**不解析 FBX，不自建 Python 3D 查看器**；3D 验证使用 Unity。
- 若现有数据无法支持正确计算，可要求上游补烘切线帧或其他必要输入；不能用缺少几何信息的公式假装恢复切线。
- Phase-1 验证公式、参数、调试数据；Phase-2 **手工重建 Pixel Processor（PP）节点图**。
- `GLSL Node` 仅为可选实验，不是依赖，不决定主路径成败。
- 第 7 节可移植性契约是硬约束；约束的是实际计算与数据语义，而不只是 GLSL 语法。

**首要风险：现有 position 已是 16-bit RGB，但错误的图片加载/纹理上传链路仍会把它降成 8 位。必须先证明全链路保真。**

## 1. 背景、适用范围与非目标

### 1.1 为什么做

各向异性高光在运行时计算有成本。本项目将指定条件下的艺术光照定格到贴图，运行时通过约定的 Unlit/自定义材质采样，避免再次执行同一套光照计算。

先用 GLSL 验证数学，再按相同语义重建 PP，比直接调试大型节点图更容易定位错误。**但不能把第一次 PP 验证留到 Phase-1 全部完成之后**：步骤 3 会提前建立小型 PP 对照图。

### 1.2 静态烘焙的边界

- 主图定格某套光照、观察假设和模型状态。相机移动、灯光改变、模型旋转或布料形变后，高光不会自动获得正确的新位置。
- `V=N` 是每个 texel 使用法线作为假想视向的艺术近似，**仍可能保留各向异性方向依赖**；它不是“任意真实视角均正确”的烘焙方法，也不应被描述为只能计算漫反射。
- 恒定 V 对应正交/远场观察近似。透视观察必须使用与 P 同空间的相机位置逐 texel 计算 V。
- N·L 只提供局部朝光判断，**不是光线可见性测试**。本版不计算投影、自阴影或褶皱之间的方向性遮挡；AO 不能替代这些效果。
- 输出是模型原烘焙 UV 上的光照颜色图，**不是 Unity 内置 GI Lightmap 数据格式**，不自动切换到 UV2。
- 本版不保证重叠 UV 上不同表面能分别存储不同光照；这在单张逐 texel 结果中通常不可实现。

## 3. 数据与坐标契约（先于光照实现）

### 3.1 高精度加载：禁止隐式降位

- `bake_position` 与 `bake_normalobj` 不得走普通 Pillow RGB 读取/转换路径。Pillow 的 RGB 模式为每通道 8 位，`I;16` 单通道支持不能替代 16-bit RGB 支持。
- 高精度 PNG 读取器默认选用 **PyPNG 的原始样本读取路径**，但必须通过步骤 1 的 RGB16 保真测试后锁定版本。任何后端只要返回 RGB8 或丢失低位，即拒收；不能只凭库名判断正确。
- 保留源 `uint16`，明确转换为 `float32 / 65535`；8-bit 数据则按 `255` 归一化。禁止依赖某个解码器自动选取分母。
- 基准实现将位置、法线等数据上传为 float32 纹理；不能先降成 8 位或 half，再扩大到 float32。
- GLSL 与 PP 的关键中间计算/输出均显式配置为 32F 基准。`float4` 表示通道与计算类型，不等于图像存储格式已经是 32F。
- Pillow 可用于适合它的 8-bit 输入、显示预览和最终 LDR PNG 输出。
- 位深优化、half 精度或其他采样优化只能在基准通过后单独验证，不属于初版默认行为。

### 3.2 颜色与数值类型

- position、所有 normal、AO、曲率、厚度、mask、ID、两张 aniso 图都是**数据**：禁止 sRGB 解码、自动颜色管理或不明确的通道转换。
- 法线的 `*2-1`、标量图的取值通道、曲率零点等均记录在 `asset_contract.json`，不分散硬编码。
- UI 输入的颜色若来自 sRGB 色值，先转换成线性 RGB；shader 中参与合成的颜色和强度均为线性量。
- 原始数据调试文件与“为了观看而着色的预览图”分开命名；不能对用于数值比较的数据图施加曝光或 sRGB 编码。

### 3.3 位置、法线、灯光与相机

- 选定一套与基准资产一致的**局部物体空间**作为计算空间，并登记坐标轴、单位和参考变换。禁止保留“世界/物体均可”的未决状态直接做点积。
- 若位置按包围盒编码，至少明确 `P = encodedP * positionScale + positionBias`。各轴独立归一化时必须恢复相应比例，不能直接把 RGB 差分当真实几何方向。
- 若需移除大的世界坐标偏移或改变单位，采用已登记的统一原点/统一比例，并对相机位置作相同变换。不得再次按各轴任意缩放几何方向。
- N、L、V、T 必须在同一计算空间；N 的轴交换/符号及源空间不能只根据文件名判断。
- L 定义为“从表面指向光源”的单位方向，本版主光为方向光。
- V 支持 `directional`（恒定方向）、`perspective`（`cameraPosition-P`）和 `normal_proxy`（V=N）三种显式模式。
- Unity 基准验证固定模型状态，先使用单位或统一缩放。非均匀缩放若未正确反映到几何和法线数据，不在已验证范围内。

### 3.4 UV、图像原点与采样

- CPU 解码后的图像采用**首行为顶部**。定义规范采样坐标 q 为左上原点、x 向右、y 向下；PP `$pos` 与此约定对齐。
- GLSL 须提供相同的 q 语义。例如由片元坐标建立 `q=(fragCoord.x/W, 1-fragCoord.y/H)`，输入按首行为顶部上传并按此 q 取样；FBO 读回时明确一次行序转换。预览显示适配也必须通过四角标记测试，不能重复翻转。
- TGA 文件原点由解码器处理到上述规范。不要看到 TGA 原点标志就无条件再翻一次。
- **图像 Y 翻转、网格 V 轴方向、法线绿色通道符号是三个不同问题。** 必须分别登记和测试。
- 求导结果先属于 q 坐标。若烘焙映射为 `q=(u,1-v)`，则网格 UV 的 `dPdu=dPdqx`、`dPdv=-dPdqy`；不得把图像向下方向直接当作作者 UV 的 +V。
- 位移步长使用**输入位置图实际尺寸**：`texel=(1/W,1/H)`。生产输出为 2048²；小型测试图使用各自尺寸，不把 1/2048 写死在公式中。
- 基准位置/法线/ID/遮罩采样固定为 mip 0、Nearest、Clamp；明确在采样前计算越界有效标记。PP 若不能直接设置某项，须在早期对照中证明其等价行为，否则门禁不通过。
- 两张 aniso 图初版也使用明确的采样配置；额外平铺、过滤、缩放或周期角度插值必须登记并另测，不能沿用隐式默认状态。
- 初版要求输入尺寸/UV 对齐，禁止悄悄 resize 数据图；预览缩放只缩放最终显示，不改变烘焙分辨率和位置求导步长。

### 3.5 必须落盘的资产契约

`asset_contract.json` 至少包括：文件路径与哈希、尺寸/源位深/通道、解码后 dtype、位置 scale/bias/单位、坐标空间、UV 集与 V 方向、UV 唯一性证据、法线轴/绿色通道约定、基底来源、coverage/island 来源、采样状态、两张 aniso 图的语义状态与证据。

未知项保持 `unverified`，不得以猜测值冒充已确认值。被启用功能所需的关键项未确认时，`--bake` 应报错；允许忽略未知可选贴图继续最小模型验证。

## 4. 逐 texel 算法与切线帧职责

以下均为数学定义；实现必须遵守第 7 节。CPU 侧参数检查、测试数据生成和辅助图处理不受“shader 禁循环/分支”的限制。

### 4.1 安全运算先于选择与遮罩

- 每次 normalize 均使用统一安全封装：先计算长度与有效标记，再以受保护分母计算候选，最后选择一个**有限、已定义**的 fallback。
- 向量形式可写为 `candidate = v / sqrt(max(dot(v,v), eps2))`，再结合有效标记选择 fallback。阈值必须适合该量的单位；几何阈值不能盲用单位向量阈值。
- fallback 仅保证数值有限，不证明方向正确。切线失效必须继续传递有效标记，不能把任意 fallback 当作有效几何。
- 为法线建立平面 fallback 时，先选择不与其近乎平行的参考轴，再叉乘归一化；不能始终使用可能平行的固定轴。
- `mix` 两侧都必须先成为合法值。禁止先产生 NaN，再试图通过乘 0、mask、clamp 或普通 mix 消除。
- 参数中的 NaN/Inf、零光向、非法范围在 CPU 入口拒绝；shader 仍保留防御性保护。

### 4.2 coverage、有效邻居与位置差分

1. 根据已确认的 mask 得到 coverage；根据已确认的岛信息限制邻域。当前可从 `mask1` 的连通域生成候选，但须先确认无重叠/贴连导致的误识别。
2. 对每个轴采中心和 ±texel 的 P，并为两个邻居分别计算有效标记：未越界、位于有效覆盖、属于允许的同岛邻域，且数据可用。
3. 两侧有效时用中心差分；仅一侧有效时用对应单边差分；两侧均无效时标记该方向失效。
4. 无分支实现可将正向差分 `(Pplus-P)/h` 与反向差分 `(P-Pminus)/h` 按各自 0/1 有效权重求平均，分母为 `max(validPlus+validMinus,1)`。所有候选样本仍必须数值有限。
5. 将 q 方向导数按第 3.4 节转换成真正的网格 U/V 导数，再构建基底。

**禁止以下伪兜底：**

- 仅凭“UV 梯度 + N”恢复与几何一致的 UV 切线：缺少绕 N 的方向信息，通常不能唯一恢复。
- 跨岛导致 T0 已错误时，仅关闭角度旋转继续使用 T0。
- 内域大面积切线失效时，通过模糊、屏蔽高光或 dilation 隐藏问题。

若解码正确的 16 位位置仍不能提供稳定方向，要求上游补烘切线帧并记录其约定。边界延拓只修复预先允许的窄边界带，不修复错误的数据编码或不可辨识的几何。

### 4.3 原始 UV 基底：不受高光参数影响

令 N0 为已解码、验证并安全归一化的基础法线，Pu/Pv 为有效的网格 UV 导数。位置差分路径的基本构造为：

```
Tu_candidate = Pu - N0 * dot(N0, Pu)
Tuv = safeNormalize(Tu_candidate, tangentFallback)
handedness_source = dot(cross(N0, Tuv), Pv)
h = handedness_source < 0 ? -1 : +1
Buv = h * cross(N0, Tuv)
```

上面的条件表达式只描述手性定义，GLSL 按契约展开为 step/mix。接近零的三重积、退化的投影或无效导数必须标记失效；不能因选出了 ±1 就算通过。

- 检查单位长度、正交性、手性及 UV 方向。**平滑不等于方向正确。**
- 镜像 UV 必须保留手性；`cross(N,T)` 不能无条件代替作者 +V。
- “主切线选 U/V”是后续各向异性方向的选择，不能交换普通法线图的解码基底。
- 位置差分得到的是近似 UV 基底，**不自动等于 MikkTSpace 或其他作者烘焙基底**。
- 若使用外部烘焙基底，按其契约解码 T、手性和参考法线，并作同样的有效性检查；不得混配不同来源的 T 与 N。

### 4.4 细节法线：先确定参考基底，再启用

默认关闭 `AnisotropicNormal`。启用普通 TS 细节模式前，必须证明它的编码和参考基底与当前解码基底匹配；否则使用补烘的匹配基底，或保持关闭。

在已确认的兼容基底中：

1. 解码原始法线，按登记的绿色通道符号处理；检查其长度/方向分布，不能仅凭“归一化后长度为 1”判定编码正确。
2. 以 `(0,0,1)` 为强度 0 的中性值，按强度混合并安全归一化，再展开 TBN 变换：`Ns = normalize(Tuv*nx + Buv*ny + N0*nz)`。
3. 强度 0 必须严格恢复 N0；原始图异常、混合退化或基底不匹配不得悄悄吞掉。

**这里使用原始作者/UV 基底，不使用旋转后的各向异性切线。** 如果确实需要“随流向旋转的沟槽模板法线”，那是另一种需明确确认的艺术模式，不属于本版普通 TS 模式。

### 4.5 在最终着色法线上建立各向异性方向

得到 Ns 后，将基础 U 方向重新投影到 Ns 的切平面，形成 `Us`；用保留的手性构造 `Vs = h*cross(Ns,Us)`，检查退化并保留有效标记。

- 主轴 `A` 按参数取 Us 或 Vs。
- 默认只有全局角度；启用角度控制图后，采用已登记的重映射。
- 自定义角度模式可定义 `theta = globalAngle + angleSign*(2*g-1)*angleRange`；单位为弧度，g=0.5 为零偏移。
- 规范正角度为绕 **+Ns 的右手旋转**。若源图按 UV 轴定义方向，解码适配必须处理镜像手性及零点差异，不能仅凭一个全局符号猜测。
- 使用 Rodrigues 向量展开。对正交单位 A/Ns，可简化为：

```
T_aniso = cos(theta)*A + sin(theta)*cross(Ns,A)
```

验证 `theta=0` 保持 A、旋转后单位长度且垂直 Ns。普通细节法线模式下，调整主轴或角度不得改变 Ns 和 N·L。

**禁止把 FX-Map 的 Pattern Rotation 或 atan2→turns 当作这里的等价替换。**

## 5. 风格化光照模型

### 5.1 视向与半角向量

- `directional`：使用规范化的恒定 V，明确为远场/正交近似。
- `perspective`：`V = safeNormalize(cameraPosition-P, viewFallback)`，相机位置与 P 同空间。
- `normal_proxy`：V=Ns，明确为艺术近似，不承诺全视角正确。
- `H = safeNormalize(L+V, halfVectorFallback)`。若 L+V 退化，令高光有效标记为 0，不使无定义向量进入后续运算。

### 5.2 位移切线双层高光

对 i=1、2 展开计算，不使用 shader 循环：

```
Ti = safeNormalize(T_aniso + Ns*shift_i, T_aniso)
c = clamp(dot(Ti,H), -1, 1)
sinTH = sqrt(max(0, 1-c*c))
aniso_i = pow(sinTH, exponent_i)
```

- `exponent_i` 必须为有限正数，初版参数范围 1–256，避免 pow(0,0) 等边界。
- shift 使用有限、受控范围；它只作用于各向异性方向，不修改普通法线图的基底。
- 如提供“各向异性程度”滑块，明确使用艺术混合，而不是把角度范围误称为强度：
  `iso_i = pow(clamp(dot(Ns,H),0,1), exponent_i)`；`raw_i = mix(iso_i,aniso_i,anisoAmount)`，其中 anisoAmount∈[0,1]。
- anisoAmount=0 时，调整各向异性角度/shift 不得改变高光；该参数不是物理粗糙度椭圆比。

### 5.3 卡通分段与局部朝光抑制

- 平滑分段要求 `0 <= edge0 < edge1 <= 1`，并保证最小间隔。为跨平台固定语义，统一展开：
  `t=clamp((x-edge0)/max(edge1-edge0,epsEdge),0,1)`；`toon=t*t*(3-2*t)`。
- 真正硬分段使用单独的 step 模式，约定 `x >= threshold` 时输出 1。禁止把 smoothstep 的两条边设成相等来模拟硬阶跃。
- 连续单层 Kajiya–Kay 为对照模式；双层、分段开关均对已经合法的数值作选择。
- 高光乘以几何/视向有效标记及 `clamp(dot(Ns,L)*frontK,0,1)`；frontK 为有限正数。
- 该项称为“局部朝光抑制”，不称为已经计算了阴影可见性。

### 5.4 漫反射、AO 与合成

- 卡通漫反射采用 `x=0.5*dot(Ns,L)+0.5` 后的同语义平滑/硬分段。阈值低于 0.5 允许艺术性 wrap/back-light，不把它当作物理 Lambert。
- AO 默认只影响环境项：`aoFactor=mix(1,clamp(ao,0,1),aoStrength)`。
- 如需 AO 同时影响直接光，提供独立、明确命名的艺术参数，默认关闭；不在不同章节里混用两种含义。
- 线性合成定义为环境项，加主光颜色/强度乘以漫反射层与两层高光之和。每层颜色、强度分别保存，不对已经累加的 HDR 光照提前截断到 1。
- 可选曲率调制、厚度透光和 rim 延后到最小模型通过之后；先明确输入中性值、映射、范围及对照用例，未实现时保持 0/关闭，不阻塞核心交付。
- albedo=白表示反照率为 1，**不是要求所有受光 texel 输出纯白**。

## 6. 边界修复、输出与 Unity 消费契约

### 6.1 有效性与 padding

- core pass 的 float4 可使用 RGB 存线性结果、A 存有效标记；其他调试量使用独立 pass，不依赖 MRT。
- 无效边界必须有独立标记，不能把“高光=0 的坏 texel”当作正确种子继续扩张。
- 只允许从**同岛有效内部 texel**向预先定义的无效边界带延拓。若修复触及未解释的内域区域，停止导出并报告根因。
- 在光照有效域修复后，再向 UV 岛外生成 padding；不得跨岛平均不同颜色。辅助处理可以多 pass/多节点，不能在 Python 中藏入 Phase-2 没有对应定义的修复逻辑。
- padding 宽度可配置，初始可用 8 texel，但这不是所有 mip/观察距离下的保证。必须在 Unity 的目标过滤、mipmap 和距离范围下验收；不足时调整 padding/UV 或明确采样范围限制。
- PP 对齐分两层验收：先比较未经边界修复的有效内域数学，再比较修复/padding；不能用边缘差异掩盖核心公式错误。

### 6.2 LDR 输出策略：只编码一次

默认使用明确的艺术性 Reinhard 输出，不依靠最后 clamp 隐藏白底高光：

```
C_exposed = max(C_linear,0) * pow(2,exposureEV)
C_ldr = C_exposed / (1+C_exposed)
C_png = standardLinearToSRGB(C_ldr)
```

- 计算、有效域延拓和 padding 在需要的线性阶段进行；量化为 PNG8 发生在输出编码之后。
- sRGB 使用标准分段传递函数，而不是任意 `pow(color,1/gamma)`。GLSL/PP 用同一展开和阈值，分支两侧都必须数值合法。
- 基准链路采用显式一次 sRGB 编码，禁止再叠加硬件 framebuffer sRGB 编码、库自动 gamma 或 Designer 导出色彩转换。
- PP 的原始数据输出与最终编码输出须分别设置；目标 Designer 版本中的 Raw/导出配置必须在早期验证并记录，不能凭默认值猜测。
- 不用额外的自由 gamma 滑块纠正错误的颜色管理。曝光是艺术参数，编码规则不是。
- 尚未用于有效域或 padding 的背景，最终可填纯白。padding 区域允许保留邻岛颜色，以避免采样渗漏。
- 主输出为不透明 RGB PNG：`out/anisotropic_lightmap.png`。该文件名沿用项目约定，但内容不是 Unity GI lightmap。

### 6.3 Unity 基准材质与场景

- 使用匹配当前渲染管线的 Unlit/自定义材质，以相同烘焙 UV 集采样主图；基础颜色为白，禁止再次计算本工具已烘焙的漫反射/高光。
- 主图按颜色纹理导入，sRGB 开启；不得作为 normal map 或数据贴图导入。
- 首次基准测试关闭纹理压缩和额外后处理/曝光/色调映射，记录模型变换、相机、纹理设置和色彩空间。随后再测试生产压缩、过滤与 mip 设置。
- 普通 Lit 材质的 BaseColor 槽不是默认消费方式，否则会重复受光。
- 不假定 `D:\Unity_Project` 就是已可启动的 Unity 工程。步骤 0 确认实际工程、Unity 版本、管线和可用于回贴的场景。

## 7. 可移植性契约（硬约束）

**适用范围：**核心着色数学及对应 PP 子图。宿主 UI、文件 IO、参数检查、测试生成可以有控制流；辅助图处理可以多 pass，但必须有可移植定义与独立验收。

| # | 约束 | 执行规则 |
|---|---|---|
| C1 | 不用 `dFdx/dFdy` | 使用显式邻域采样；步长来自输入尺寸，处理 coverage/同岛/单边差分 |
| C2 | 核心不使用 `mat2/3/4` | TBN、空间变换和旋转按向量/分量展开；这是本项目选定的表达子集，不借此断言 PP 本体不支持某种数学 |
| C3 | 核心不使用 `for/while` | 双层高光等有限重复直接展开；这是简化手工重建的项目约束，不声称 PP 完全没有循环能力 |
| C4 | 核心不使用 `if` 或条件运算符 | 用数值比较、step、mix 等表达；先保证全部候选合法，禁止把无分支选择当作 NaN 保护 |
| C5 | 运算语义一致 | 使用加减乘除、dot/cross、min/max/clamp、abs、sqrt、sin/cos、pow、mix、step 及本计划的安全/分段封装；三角输入统一弧度，不套用 FX-Map Pattern Rotation |
| C6 | 保持可机械映射的模块 | 参数名使用 `p_`/`a_` 等前缀避免内联冲突；为安全归一化、基底、旋转、单层高光、编码建立固定输入/输出定义 |
| C7 | 每 pass 单一 float4 | 调试量分 pass 输出；明确 alpha 含义。不能把 float4 与 32F 存储、或单输出与必须单 pass 混为一谈 |
| C8 | 采样与精度一致 | 固定 q 原点、UV 方向、像素中心、源尺寸、过滤、寻址、mip 和数据精度；未核实的 PP 行为不能写成既定事实 |
| C9 | 参数与颜色一致 | 同一资产契约和参数快照；线性计算、相同输出曲线、一次 sRGB 编码；数据调试与显示调试分离 |

补充规则：

- 不因函数同名就假定参数顺序、角度单位、边界行为一致；只实现本版真正需要的函数，并在最小 PP 图中验证。
- 原始 UV 基底、最终 Ns 和 T_aniso 是不同角色，Phase-2 不得合并成一个含糊的 TBN。
- PP 图像输入上限按目标版本核实，不能凭“Python 加载 10 张图”推断必须绑定 10 个输入。主路径列出实际绑定表，备用图可使用独立校验 pass。
- 必要时进行通道打包或拆辅助节点，但数据格式与语义必须明示并测试。
- `GLSL Node` 的限制只归属于可选翻译器；不以插件成败证明或否定手工 PP 路线。

## 8. 参数、预览与可复现交付

### 8.1 参数清单

- **光照**：方向 XYZ（规范值）及方位/仰角 UI、线性光色/强度、环境色/强度。角度 UI 的轴定义须记录，保存时保留规范方向。
- **观察**：directional / perspective / normal_proxy；方向或局部相机位置。
- **方向场**：主轴 U/V、全局角度、角度图状态/模式、范围/零点/符号。
- **各向异性程度**：anisoAmount，0 为本文定义的各向同性对照，1 为各向异性模型。
- **高光**：shift1/2、exponent1/2、连续/平滑分段/硬分段、各层阈值、颜色与强度、frontK。
- **法线**：语义状态、已验证的解码模式、绿色通道符号、细节强度。普通模式不随方向图旋转。
- **漫反射与调制**：分段阈值、颜色、AO 强度；AO 直接光影响默认 0；曲率/透光/rim 初始关闭。
- **输出**：exposureEV、padding 宽度、调试输出选择；不把显示 gamma 当作算法校正参数。

默认安全状态：两张未知语义的 aniso 图关闭；先使用基础方向场验证，之后按证据或确认的艺术解释启用。所有开关、阈值和版本都进入快照，不能只保存可见的滑块。

### 8.2 运行模式

- `--preview`：moderngl-window + 可选 imgui；核心仍在固定烘焙分辨率 FBO 中计算，窗口只显示缩放后的结果。
- `--bake`：从同一配置创建 standalone context，运行同一计算与输出链路。无窗口不等于不需要 GPU/驱动，步骤 0 验证 Windows 环境是否支持。
- 缺少 imgui 时可通过配置和简单键盘控制工作，不阻塞离线导出。
- 预览保存和无头读取必须使用同一个参数校验器；无效配置报出字段与原因，不静默修正为另一套参数。

### 8.3 调试与可复现文件

必备调试量：源数据保真输出、coverage/island、导数与 frame validity、Tuv/Buv、Ns、T_aniso、原始/分段高光、N·L、未编码线性光照及最终图。

- `config.json`：艺术参数及指向资产契约的引用。
- `asset_contract.json`：数据/空间/基底/语义约定及证据。
- 每次正式导出保存二者快照、输入哈希、依赖/引擎版本、采样/颜色配置和校验结果。
- 数值数据优先使用 float32 文件。PP 若通过文件对照，可使用可保真的浮点格式，或有明确 scale/bias 的 16 位 Raw 数据图；不能让负数/HDR 值被截断后再比较。
- PNG 预览不是数值真值；同样尺寸和“看着一样”不能替代数据验收。

## 10. 执行工单与阶段门禁

**任何一步的结构性错误未解决，不得靠“先记下来”越过门禁。**

### 步骤 0 — 环境、资产与范围确认

- 确认 Python 可执行文件、依赖版本、OpenGL/standalone 能力、Designer 版本和实际 Unity 工程/管线。
- 核实文件头与通道；从上游查明位置归一化、空间、UV 集和法线约定，填写资产契约。
- 确认 UV 唯一性及 coverage/island 的适用性；仅看二值 mask 不能证明网格没有重叠 UV。
- 登记未知可选图为关闭，不伪造其语义；列出补烘需求及负责人/所用上游工程。
- **门禁 G0：**基础 P/N/UV 的关键契约可被验证；环境有可执行路径。关键几何信息缺失时，只能继续做合成数据实验，不能声称实资产已可烘焙。

### 步骤 1 — 最小骨架与高精度数据通路

- 建立空 pass、离屏/预览共享链路，输出 2048² 测试图。
- 使用独立生成的 RGB16 测试图，包含仅低位不同的相邻样本、三通道不同值和四角标记。
- 验证解码 dtype/位深、归一化、上传、采样和读回没有降位、gamma、通道交换或双重翻转。
- 明确数据直出与显示编码的区别。不得以把 16 位源图先转成 RGB8 再“往返一致”作为成功证据。
- **验收：**相邻低位差异保留，数据误差符合 float32/已声明量化界限；实际 position/normalobj 沿同一保真路径加载。

### 步骤 2 — 最小几何、法线与单层高光

- 先关闭两张未知语义图、双层分段及可选调制，仅验证基础切线和连续高光。
- 使用已知答案的普通平面、旋转 UV 平面、镜像 UV、斜向法线平面、UV 边界与孤立/退化 texel。
- 验证 Tu/Bu/N 的长度、正交性与手性；验证 q→网格 UV 的导数符号，不能只看切线颜色平滑。
- 添加受控 TS 法线测试：强度 0 恢复 N0；镜像区域绿色通道倾斜正确；改变各向异性角度不改变 Ns/N·L。
- **门禁 G1：**合成例通过；实际资产内域无未解释的失效方向，允许修复的边界带单独标明。位置差分不合格则补烘基底，不进入完整高光开发。

### 步骤 3 — 提前建立最小 PP 对照（Phase-1 内的兼容性探针）

- 在目标 Designer 中手工建立小型 `aniso_probe.sbs`，验证采样、精度、q 原点、安全归一化、手性、三维旋转和单层高光。
- 验证 0、±π/2、π 旋转及任意非 Z 法线轴；保留局部三维基底，不使用 FX-Map Pattern Rotation。
- 验证 L=-V、零向量、根号边界、非法阈值拒收，以及标准输出编码测试块。
- 固定实际 PP 纹理输入绑定、格式、采样与 Raw/导出设置，并记录版本。
- **门禁 G2：**同输入/参数的有效内域数值对齐，而不只是截图相似。输入数上限等没有证据的能力，不预先写死或假定。

### 步骤 4 — 提前 Unity 回贴

- 用最小模型输出建立第 6.3 节的 Unlit 基准场景，验证 UV 集、方向、色彩与静态观察假设。
- 检查接缝和回贴朝向，保留固定相机截图及导入设置；不新增 Python 3D 渲染器。
- **验收：**没有重复受光、错误 UV、错误色彩转换；若实际需要阴影或动态高光，在这里反馈范围差异，不能等 UI 完成再发现。

### 步骤 5 — 完整风格化核心与已确认的输入语义

- **验收：**每项参数作用可解释；0 强度/关闭模式可回归基准；全参数合法范围内无 NaN/Inf。

### 步骤 6 — UI、无头复现与生产输出

- 接入完整参数、配置校验和快照；加入有效域修复、padding、正式导出及诊断报告。

- 回贴 Unity 检查生产压缩、过滤、mip 与目标距离下的接缝/闪烁，记录静态使用限制。
- **门禁 G3：**核心内域、边界修复、导出和消费端均通过，未解释的无效像素或颜色异常不能靠曝光掩盖。

### 步骤 7 — Phase-2 完整手工重建

- 在已通过的 PP 探针上扩展，而不是重新选择旋转/基底算法。
- 重建安全运算、基底、细节法线、三维旋转、双高光、合成、边界处理与输出编码；参数含义与默认值完全一致。
- `GLSL Node` 可另作实验，但验收只依赖手工 PP 路径。
- 交付 `.sbs`、参数/输入映射表、版本设置及逐层数值/Unity 回贴报告。

### 统一数值验收规则

- 所有正常计算及明确测试的退化路径，NaN/Inf 数必须为 0；退化几何仍须报告，不能被安全 fallback 冒充有效方向。
- 有效单位向量的长度/正交误差初始阈值为 1e-4，并检查方向与手性，不只检查长度。
- 有效内域的 float32 中间量初始采用最大绝对误差 1e-4、RMSE 1e-5；若通过 16 位数据文件比较，须显式加入其 scale/bias 对应的量化误差并登记阈值。
- 硬阶跃附近单独测试规定的等号语义；浮点临界样本比较原始高光/阈值距离，不以其不连续性为由忽略大范围差异。
- 同环境预览/无头的最终 PNG 目标为像素一致；跨平台最终 PNG 有效内域以每通道 2 LSB 为初始目标，并结合原始数值定位差异。
- 边界/padding 使用独立允许区域与指标，不能把整张图都放入“允许边缘细微差异”。任何放宽须有原因、样本和记录。
- 白底 HDR 用例必须验证两个不同的高光亮度经过默认输出曲线后仍可区分；不能全部饱和为 255。

### 11.1 必须明确传达给执行者

1. **先保真，再求切线，再验证 PP/Unity，最后做完整 UI。** 高精度源图存在，不代表读取链路已经高精度。

### 11.3 参考与证据用途

- [Pillow Concepts](https://pillow.readthedocs.io/en/stable/handbook/concepts.html)：RGB 模式位深与多通道高位深限制；不要将单通道 I;16 支持误用于 RGB16。

- [UnityURPAnisoHighlightHairShader](https://github.com/cathyhlshih/UnityURPAnisoHighlightHairShader)：可参考方向纹理参与风格化高光的思路；README 未证明本项目两张图的通道/零点/范围语义。
- Kajiya–Kay（1989）及位移双层高光可作为算法思路参考。其他动漫 shader 仓库应逐一核对许可；不搬运受限代码，也不把“某游戏同款”的说法当作技术正确性证据。
